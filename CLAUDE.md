# CLAUDE.md — carbsaresugar.com

## What this is

A sugar teaspoon calculator. Users tap foods; the site totals how many 4g teaspoons of table sugar would have the same blood glucose effect, using Dr David Unwin's glycaemic load method (Unwin, Haslam, Livesey, J Insulin Resist 2016;1(1):a8) and the PHC infographics at https://phcuk.org/sugar/.

Stack: Astro 4 static output, Tailwind 3, vanilla TypeScript for the calculator. No React, no server code, no storage. Fonts self-hosted via @fontsource. Only third-party script: Google AdSense (in `src/layouts/Layout.astro`).

## The conversion is GL ÷ 2.73, not GL ÷ 4

Unwin 2016 Box 2: a 4g teaspoon of sucrose = 4.2g carbohydrate (monosaccharide equivalent) × GI 65 ÷ 100 = GL 2.73. Every published infographic value reproduces with ÷2.73. Dividing by 4 would understate every food by about a third. Do not "fix" this to 4.

## Data policy

- `src/data/foods.json` is generated by a Python script kept outside the repo during the build session; edit the JSON directly now, but keep every rule below.
- Every food has `source` (an id in `sources.json`), `derivation` (`read from infographic` | `published GL table` | `calculated from GI and carb content`) and `notes`.
- `cubes` is always the published teaspoon figure. Where a source prints no GL, `gl` is back-calculated as cubes × 2.73 and the note says so.
- Never invent a value. If a food has no defensible published figure, leave it out.
- Where two PHC charts disagree, pick one, record the other in `notes`, and list it on `/sources/`.
- Update `last_verified` in `sources.json` only after actually re-checking values.

## Gotchas

- `@astrojs/sitemap` pinned at 3.2.1 (3.7.x crashes on Astro 4.16).
- Tabs must keep `flex-wrap`. Never switch to horizontal scroll.
- Elements toggled with the `hidden` attribute must not carry a Tailwind display utility (`flex`, `block`), or the utility wins and they stay visible.
- `/privacy/` describes behaviour verified in a browser. If you add any script, storage, font service or request, re-verify and update that page in the same change.
- No `_headers` / `_redirects`. Cloudflare Pages handles caching.
- `.github/workflows/validate-data.yml` checks source URLs and a hash of the PHC page's visible text (`phc_page_text_sha256`). If PHC changes the page cosmetically, update the stored hash after review.

## Copy rules

Sentence case, no exclamation marks, never "shocking", "hidden", "truth". Show data side by side; never tell the reader what to eat.
